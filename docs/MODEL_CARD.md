# Карточка моделей FaceSwapLocal — этапы B и E1

Дата проверки источников и условий: этап B — 19.07.2026; модели этапа E1
(`gfpgan_1.4`, `bisenet_resnet_34`) — 23.07.2026; повторная сверка лицензий четырёх
моделей этапа B по первоисточникам — 23.07.2026.

Этот документ описывает ровно те файлы ONNX, с которыми выполнены этапы B и E1. Веса не
входят в репозиторий или APK. Приложение не скачивает их: пользователь выбирает каждый
файл системным picker, после чего приложение проверяет точный размер и полный SHA-256
до помещения файла в приватное хранилище и повторяет проверку перед созданием сессии.

SHA-256 взят из Xet/LFS metadata официальных страниц файлов Hugging Face на
зафиксированных ревизиях и повторно проверен локально после скачивания. Сопутствующие
файлы `*.hash` в репозиториях FaceFusion содержат восьмизначную контрольную сумму, а не
полный SHA-256; приложение их не использует.

После первой полной успешной SHA-256-проверки в процессе приложения `ModelStore`
запоминает `ModelId`. При последующих открытиях ONNX-сессии в том же процессе
проверяются канонический путь в приватном `filesDir/models` и точный размер файла;
после перезапуска процесса полная SHA-256-проверка выполняется заново. Импортируемый
файл всегда полностью хешируется до атомарной установки.

Правовой статус весов не позволяет считать их безопасными для распространения внутри
репозитория или APK:

- репозитории `facefusion/models-*` на зафиксированных ревизиях не содержат полного
  текста лицензии, однозначно предоставляющего право перераспространять эти четыре
  файла;
- для HyperSwap в FaceFusion указан только ярлык `ResearchRAIL`, без варианта, версии и
  полного текста условий;
- для моделей InsightFace официально заявлено использование только для
  некоммерческих исследовательских целей; для `inswapper` отдельно предлагается
  обращаться к InsightFace за лицензией;
- у `yoloface_8n` расходятся ярлык FaceFusion `GPL-3.0` и встроенное в ONNX значение
  `AGPL-3.0 https://ultralytics.com/license`.

Поэтому решение проекта едино для всех весов: **не коммитить, не включать в APK и не
перераспространять**. Импорт через picker переносит выбор файла и ответственность за
соблюдение его условий на локального пользователя, но сам по себе не создаёт права на
использование. Это документирование не является юридической консультацией.

**Коммерческое использование этой сборки невозможно без замены моделей.** Как минимум
`arcface_w600k_r50` и `inswapper_128_fp16` (InsightFace, non-commercial research;
inswapper — отдельный запрос лицензии), а с этапа E1 и `gfpgan_1.4` (составная лицензия
с некоммерческими компонентами NVIDIA-NC и CC-BY-NC-SA, см. §8) допускают только личное
некоммерческое использование. Любое коммерческое применение требует замены этих моделей
на весы с подходящей лицензией и повторной проверки parity.

## 2. Общий препроцессинг и выравнивание

Источником истины служит FaceFusion 3.7.1, tag `3.7.1`, commit
`3f81a8a78454089d720b8f318a12ae1702c4633b`. Kotlin-реализация использует пять точек
нейросетевого детектора; точки ML Kit применяются только для быстрого UI-preview и в
модельный pipeline не передаются.

Пять точек идут в порядке: левый глаз, правый глаз, нос, левый угол рта, правый угол
рта. По ним строится orientation-preserving least-squares similarity transform. Точки
шаблонов ниже нормированы к ширине и высоте кропа.

`arcface_112_v2` для identity encoder:

```text
(0.34191607, 0.46157411)
(0.65653393, 0.45983393)
(0.50022500, 0.64050536)
(0.37097589, 0.82469196)
(0.63151696, 0.82325089)
```

`arcface_128` для обоих swapper:

```text
(0.36167656, 0.40387734)
(0.63696719, 0.40235469)
(0.50019687, 0.56044219)
(0.38710391, 0.72160547)
(0.61507734, 0.72034453)
```

На этапе B детектор FaceFusion и Android используют исходные пять точек YOLO. В
production-пути FaceFusion может уточнять геометрию через 68-точечный landmarker; такое
уточнение и защита областей перекрытия относятся к последующим этапам. Это отклонение
зафиксировано и одинаково применено по обе стороны parity-теста.

Низкоуровневое отличие Android также зафиксировано: вместо FaceFusion/OpenCV
`estimateAffinePartial2D(RANSAC, 100)` используется детерминированное closed-form
least-squares решение, а вместо `warpAffine(INTER_AREA, BORDER_REPLICATE)` — bilinear
inverse sampling с ограничением координат краем. Числовые шаблоны не изменены.
Обоснование и измеренные допуски приведены в `docs/parity/README.md`; минимальный SSIM
кропа 0,997606 подтверждает это отклонение на parity-наборе, но не отменяет проверки
будущих сложных ракурсов.

## 3. `yoloface_8n`

### Идентификация и источник

- Название / версия: `yoloface_8n.onnx`, идентификатор версии — точный файл на revision
  `728b9659bd9691bf32cbf7f61af478d94b7ba81e`.
- Автор / организация: FaceFusion указывает vendor `derronqi`, 2022; встроенные ONNX
  metadata указывают author `Ultralytics`, exporter version `8.1.0`.
- Первичный файл для данного reference-набора:
  <https://huggingface.co/facefusion/models-3.0.0/blob/728b9659bd9691bf32cbf7f61af478d94b7ba81e/yoloface_8n.onnx>.
- Размер: 12 659 761 байт.
- SHA-256: `821cdbb1e65fbbabdde7dd0933f754797a343e56fd962729c61ffcefcd135929`.

### Лицензия и допустимость

- FaceFusion 3.7.1 маркирует модель одним словом `GPL-3.0`:
  <https://github.com/facefusion/facefusion/blob/3.7.1/facefusion/face_detector.py>.
- **Этот ярлык занижает реальные условия.** Внутри самого ONNX записано
  `AGPL-3.0 https://ultralytics.com/license`, author `Ultralytics`. Модель — экспорт
  `yolov8-face` (derronqi) на базе Ultralytics YOLOv8, чей публичный лиценз —
  **AGPL-3.0**. AGPL-3.0 строже GPL-3.0: добавляет сетевой (network/service) copyleft.
  Проверено по первоисточнику 23.07.2026: <https://github.com/ultralytics/ultralytics>
  (LICENSE = AGPL-3.0).
- Действующей считается **AGPL-3.0** (сильнее ярлыка FaceFusion); суффикс
  `-only` / `-or-later` upstream явно не проставлен.
- Личное использование: отдельное разрешение для данного файла и его обучающих данных
  на странице модели не найдено; проект ограничивает работу локальным тестированием и
  не утверждает более широкого права.
- Распространение в APK / репозитории: **нет** до документированного разрешения и
  устранения расхождения лицензий.

### Формат и tensor contract

- Формат: ONNX, float32 I/O.
- Вход: `input`, `[1, 3, 640, 640]`.
- Выход: `output`, `[1, 20, 8400]`; bbox, confidence и пять точек с confidence.
- Препроцессинг: сохранение пропорций, размер не увеличивается выше исходного; рабочая
  область размещается слева сверху в 640×640, остаток заполнен нулями; channel order
  BGR, NCHW, диапазон `[0, 1]`.
- Postprocessing: threshold `0.5`, NMS IoU `0.4`, координаты возвращаются в исходное
  изображение.
- Alignment: сама модель не выравнивает лицо, а предоставляет пять точек для шаблонов
  из раздела 2.

### Ограничения и измерения

- Маленькие, сильно повёрнутые и перекрытые лица могут не пройти threshold или дать
  неточные точки. На этапе B не используется дополнительный 68/106-point landmarker.
- На эмуляторе Android 15 / API 35, x86_64, 2 ГБ RAM, ONNX Runtime 1.26.0 CPU EP,
  детекция source+target занимала 2 201–2 813 мс в шести финальных parity-прогонах.
- Benchmark на реальном Android-устройстве: не выполнялся — подключённого физического
  устройства на этапе B не было; эмулятор не объявляется reference device.

## 4. `arcface_w600k_r50`

### Идентификация и источник

- Название / версия: `arcface_w600k_r50.onnx`, точный файл на revision
  `728b9659bd9691bf32cbf7f61af478d94b7ba81e`.
- Автор / организация: InsightFace; backbone ResNet-50, WebFace600K.
- Первичный файл для данного reference-набора:
  <https://huggingface.co/facefusion/models-3.0.0/blob/728b9659bd9691bf32cbf7f61af478d94b7ba81e/arcface_w600k_r50.onnx>.
- Официальная политика InsightFace:
  <https://github.com/deepinsight/insightface#license>.
- Размер: 174 388 474 байта.
- SHA-256: `f1f79dc3b0b79a69f94799af1fffebff09fbd78fd96a275fd8f0cbbea23270d1`.

### Лицензия и допустимость

- FaceFusion маркирует веса как `Non-Commercial`.
- InsightFace разрешает предоставленные pretrained models только для
  `non-commercial research purposes`; MIT относится к коду InsightFace, а не к весам.
- Личное использование: подтверждено только в той мере, в какой оно является
  некоммерческим исследованием/оценкой; обычное бытовое использование отдельно не
  разрешено опубликованным текстом.
- Распространение в APK / репозитории: **нет**. Для иных условий необходимо письменное
  разрешение InsightFace.

### Формат и tensor contract

- Формат: ONNX, float32.
- Вход: `input`, `[N, 3, 112, 112]` (в текущем pipeline `N=1`).
- Выход: `output`, `[1, 512]`, raw identity embedding.
- Alignment: пять точек, шаблон `arcface_112_v2`, кроп 112×112.
- Препроцессинг: RGB, NCHW, `x / 127.5 - 1`, то есть диапазон `[-1, 1]`.
- Конвертация для HyperSwap: L2-нормализация raw embedding.
- Конвертация для InSwapper: используется raw embedding и матрица `emap` из initializer
  самого `inswapper_128_fp16`; точная формула приведена в разделе 6.

### Ограничения и измерения

- Вектор является биометрическим признаком. FaceSwapLocal держит его только в памяти
  текущей операции, не пишет в БД или файл и освобождает вместе с задачей.
- Возможны ошибки идентичности и неодинаковое качество для разных возрастов, оттенков
  кожи, ракурсов и освещения; отдельная fairness-валидация не выполнена.
- На эмуляторе API 35 CPU inference занимал 3 411–4 270 мс на один source crop.
- Benchmark на реальном Android-устройстве: не выполнялся по причине отсутствия
  подключённого физического устройства.

## 5. `hyperswap_1a_256`

### Идентификация и источник

- Название / версия: `hyperswap_1a_256.onnx`, FaceFusion model family 1a, 2025,
  точный файл на revision `6271ab1c4619ceb2e534d65e0ec973f22a9aec38`.
- Автор / организация: FaceFusion.
- Первичный источник:
  <https://huggingface.co/facefusion/models-3.3.0/blob/6271ab1c4619ceb2e534d65e0ec973f22a9aec38/hyperswap_1a_256.onnx>.
- Размер: 402 742 682 байта.
- SHA-256: `c0e98a8a03a238f461ed3d2570e426b49f46745ee400854a60dceeb70c246add`.

### Лицензия и допустимость

- FaceFusion 3.7.1 публикует для модели ровно ярлык `ResearchRAIL`:
  <https://github.com/facefusion/facefusion/blob/3.7.1/facefusion/processors/modules/face_swapper/core.py>.
- Полный идентификатор лицензии: **не установлен** — вариант/версия ResearchRAIL и
  полный текст условий отсутствуют в model repository на проверенной ревизии.
- Личное использование: **не подтверждено явным лицензионным текстом**; локальная
  parity-оценка не трактуется как разрешение на иное использование.
- Распространение в APK / репозитории: **нет**.

### Формат и tensor contract

- Формат: ONNX; веса графа fp16, I/O float32.
- Вход `source`: `[1, 512]`, L2-нормализованный ArcFace embedding.
- Вход `target`: `[1, 3, 256, 256]`.
- Выход `output`: `[1, 3, 256, 256]`.
- Выход `mask`: `[1, 1, 256, 256]`.
- Alignment target: пять точек, шаблон `arcface_128`, кроп 256×256.
- Препроцессинг target: RGB, NCHW, `(x/255 - 0.5) / 0.5`, диапазон `[-1, 1]`.
- Визуализация raw output: `output * 0.5 + 0.5`, затем clamp `[0, 1]`.

### Ограничения и измерения

- На трёх синтетических парах raw SSIM к FaceFusion составил
  `0.9975128–0.9980599`, то есть tensor pipeline совпал с эталоном.
- При визуальной проверке этих же пар перенос identity оказался заметно слабее, чем у
  InSwapper: raw crop сохранял слишком много признаков target. Поэтому модель остаётся
  основным кандидатом shortlist, но не принята как рабочий default этапа B; дефект не
  маскируется высоким SSIM, потому что эталонный raw output ведёт себя так же.
- На эмуляторе API 35 CPU swapper inference занимал 16 238–18 138 мс; полный pipeline
  22 514–24 482 мс.
- Benchmark на реальном Android-устройстве: не выполнялся из-за отсутствия устройства.

## 6. `inswapper_128_fp16`

### Идентификация и источник

- Название / версия: `inswapper_128_fp16.onnx`, fp16-вариант семейства InSwapper,
  точный файл на revision `728b9659bd9691bf32cbf7f61af478d94b7ba81e`.
- Автор / организация: InsightFace.
- Файл reference-набора:
  <https://huggingface.co/facefusion/models-3.0.0/blob/728b9659bd9691bf32cbf7f61af478d94b7ba81e/inswapper_128_fp16.onnx>.
- Официальная политика и контакт для лицензирования InSwapper:
  <https://github.com/deepinsight/insightface#license>.
- Размер: 277 680 829 байт.
- SHA-256: `c4eccca86ad177586c85c28bf1a64a9d9ed237e283a15818d831f7facfd3f420`.

### Лицензия и допустимость

- FaceFusion маркирует веса как `Non-Commercial`.
- InsightFace ограничивает pretrained models некоммерческими исследовательскими
  целями и с 24.11.2025 отдельно просит обращаться за лицензией для серии InSwapper.
- Личное использование: подтверждено только для некоммерческого исследования/оценки;
  более широкое личное использование не заявлено.
- Распространение в APK / репозитории: **нет**; для дополнительных прав требуется
  лицензия InsightFace.

### Формат, tensor contract и embedding conversion

- Формат: ONNX; веса графа fp16, I/O float32.
- Вход `target`: `[1, 3, 128, 128]`.
- Вход `source`: `[1, 512]`.
- Выход `output`: `[1, 3, 128, 128]`.
- В графе находится initializer `initializer` (`emap`) размера `[512, 512]`.
- Alignment target: пять точек, шаблон `arcface_128`, кроп 128×128.
- Препроцессинг target: RGB, NCHW, диапазон `[0, 1]`, без дополнительной
  нормализации.
- Identity conversion, строго как в FaceFusion 3.7.1:
  `source = raw_arcface_embedding @ emap / ||raw_arcface_embedding||₂`.
- Raw output интерпретируется как RGB NCHW в диапазоне `[0, 1]`.

### Ограничения и измерения

- Рабочее разрешение 128×128 ограничивает детали на 12-МП фото. Этот raw crop не
  является финальным качеством: inverse transform/blending выполняются на этапе C,
  GFPGAN 1.4 и управляемое восстановление — на этапе E.
- На трёх синтетических парах raw SSIM к FaceFusion составил
  `0.9975512–0.9982747`; во всех трёх crop визуально переносил личность source. Поэтому
  InSwapper выбран фактическим fallback/default для продолжения после этапа B.
- На эмуляторе API 35 CPU swapper inference занимал 32 799–33 474 мс; полный pipeline
  39 310–40 212 мс.
- Benchmark на реальном Android-устройстве: не выполнялся из-за отсутствия устройства.

## 7. Parity и известные артефакты

Эталон: FaceFusion 3.7.1, Python 3.12.10, ONNX Runtime 1.26.0,
`CPUExecutionProvider`, OpenCV 4.13.0, NumPy 2.2.1. Android: эмулятор API 35 x86_64,
ONNX Runtime Android 1.26.0, CPU EP. Использованы три полностью синтетические пары.

- максимальное расхождение пяти точек: `0.123990 px`;
- SSIM выровненных кропов: не ниже `0.997606`;
- raw SSIM HyperSwap: не ниже `0.9975128`;
- raw SSIM InSwapper: не ниже `0.9975512`;
- обязательный порог §11.4 `0.95` пройден всеми шестью запусками.

Команды, версии и артефакты находятся в `docs/parity/`; численные Android-результаты —
в `docs/parity/android/api35-x86_64/android_results.json`, desktop reference — в
`docs/parity/reference/facefusion-3.7.1/desktop_results.json`. Общие измерения и
ограничения устройства фиксируются в `docs/BENCHMARKS.md`.

Не выполнено на этапе B:

- benchmark и memory profiling на физическом reference device;
- refined landmarks, face parsing, occlusion mask, inverse transform и blending;
- GFPGAN 1.4;
- проверка качества на личных фото — личные изображения не использовались и не
  коммитились.

## 8. Модели этапа E1

Веса не входят в Git/APK; импорт и проверка SHA-256 — как для моделей этапа B.

### 8.1 `gfpgan_1.4` (восстановление деталей лица)

#### Идентификация и источник

- Название / версия: `gfpgan_1.4.onnx`, GFPGAN v1.4 (arch clean, без цветокоррекции).
- Автор / организация: TencentARC.
- Файл для сборки: <https://huggingface.co/facefusion/models-3.0.0/blob/main/gfpgan_1.4.onnx>
  (скачан 23.07.2026 через `resolve/main`).
- Upstream-проект и первичная лицензия: <https://github.com/TencentARC/GFPGAN>.
- Размер: 340 299 087 байт.
- SHA-256: `accc4757b26bdb89b32b4d3500d4f79c9dff97c1dd7c7104bf9dcb95e3311385`.

#### Лицензия и допустимость (составная — ярлык FaceFusion `Apache-2.0` неполон)

FaceFusion 3.7.1 маркирует модель одним словом `Apache-2.0`. Реальные условия —
**составные**, потому что GFPGAN включает компоненты с собственными лицензиями:

  upstream: «GFPGAN is released under Apache License Version 2.0.»
- **NVIDIA Source Code License (Non-Commercial)** — архитектура StyleGAN2, на которой
  основан декодер GFPGAN: <https://nvlabs.github.io/stylegan2/license.html>. Разрешает
  только некоммерческое использование.
- **CC-BY-NC-SA 4.0** — компоненты, унаследованные от DFDNet:
  <https://creativecommons.org/licenses/by-nc-sa/4.0/>. Non-Commercial + ShareAlike.
- Транзитивно: BasicSR и facexlib — Apache-2.0; torch/torchvision/numpy — BSD-3.

**Результирующее ограничение:** из-за компонентов NVIDIA-NC и CC-BY-NC-SA использование

#### Формат и tensor contract

- Формат: ONNX, float32 I/O.
- Вход `input`: `[1, 3, 512, 512]`. Модель не имеет входа `weight` (сила восстановления
  задаётся не входом модели, а внешним blend — см. ниже).
- Выход `output`: `[1, 3, 512, 512]`.
- Alignment: пять точек, шаблон `ffhq_512` (**отличается от `arcface_128` swapper'а**),
  кроп 512×512. Точки шаблона (нормированы):
  `(0.37691676,0.46864664) (0.62285697,0.46912813) (0.50123859,0.61331904)`
  `(0.39308822,0.72541100) (0.61150205,0.72490465)`.
- Препроцессинг (порт из FaceFusion `prepare_crop_frame`): RGB, `x/255`, затем
  `(x-0.5)/0.5` → диапазон `[-1, 1]`, NCHW.
- Постпроцессинг (`normalize_crop_frame`): clip `[-1,1]`, `(x+1)/2`, `*255`, обратно RGB.
- Сила восстановления (FR-PHOTO-05): выход GFPGAN смешивается с до-восстановительным
  кропом свапа коэффициентом `blend ∈ [0,1]`, default **0.8** (не 1.0), чтобы не терять
  идентичность и не «пластилинить» лицо. Крайние значения проверяются визуально.

#### Ограничения

- Обучен на FFHQ; на нетипичных ракурсах/освещении возможны артефакты.
- Применяется только к области лица (кроп + parser-маска), не к фону и волосам.

### 8.2 `bisenet_resnet_34` (face parser для маски)

#### Идентификация и источник

- Название / версия: `bisenet_resnet_34.onnx`, BiSeNet ResNet-34 face parser.
- Автор / организация: BiSeNet (CoinCheung); face-parsing адаптация zllrunning.
- Файл для сборки: <https://huggingface.co/facefusion/models-3.0.0/blob/main/bisenet_resnet_34.onnx>
  (скачан 23.07.2026 через `resolve/main`).
- Upstream: <https://github.com/zllrunning/face-parsing.PyTorch>,
  <https://github.com/CoinCheung/BiSeNet>.
- Размер: 93 632 546 байт.
- SHA-256: `4a0b8c958a3c938913bd06a8365dbb3c8761afba6ecbf0d14b3b1f77eb230c96`.

#### Лицензия и допустимость

- FaceFusion 3.7.1 маркирует модель как `MIT`. Первоисточники (CoinCheung/BiSeNet и
  zllrunning/face-parsing.PyTorch) распространяются под **MIT** — сверено 23.07.2026,
  расхождений с ярлыком не обнаружено. MIT разрешает в т.ч. распространение, однако для
  единообразия проекта веса всё равно не коммитятся и импортируются локально.

#### Формат и tensor contract

- Формат: ONNX, float32.
- Вход `input`: `[batch, 3, 512, 512]` (в pipeline `batch=1`).
- Выходы: три (BiSeNet main + два auxiliary); используется основной выход как логиты
  сегментации `[1, 19, 512, 512]`.
- Препроцессинг (порт из FaceFusion `create_region_mask`): resize 512×512, RGB, `x/255`,
  вычесть ImageNet mean `[0.485,0.456,0.406]`, поделить на std `[0.229,0.224,0.225]`,
  NCHW.
- Постпроцессинг: `argmax` по каналам классов; маска = принадлежность к защищаемым
  регионам. Карта классов FaceFusion: `skin=1, left-eyebrow=2, right-eyebrow=3,
  left-eye=4, right-eye=5, glasses=6, nose=10, mouth=11, upper-lip=12, lower-lip=13`.
  Волосы (класс 17) и фон в маску не входят — так восстановление не заходит на волосы и
  соседние области. Далее resize к размеру кропа, GaussianBlur σ≈5,
  `(clip(0.5,1)-0.5)*2`.
- Итоговая маска восстановления = `min(box_mask, region_mask)` (пересечение), т.е.
  восстановление применяется только внутри защищённой области лица.

#### Ограничения

- Occlusion-модель (`xseg`, GPL-3.0) на этапе E1 **не подключается** (см.
  `docs/KNOWN_LIMITATIONS.md`): руки/предметы перед лицом parser-маска не защищает.
- Parser добавляет отдельную ONNX-сессию; она загружается по требованию и выгружается
  после задачи (§5.2), не удерживается одновременно со swapper.
